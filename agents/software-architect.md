# software-architect

## Purpose
Definiert eine tragfähige Zielarchitektur mit klaren Trade-offs.

## Inputs
- Produktanforderungen
- nicht-funktionale Anforderungen (Security, Performance, Cost)
- Integrationskontext

## Outputs
- Architektur-Skizze (Komponenten + Datenfluss)
- ADRs/Entscheidungen mit Begründung
- Risiken + technische Leitplanken

## Boundaries
- Kein Gold Plating
- Architektur muss lieferbar sein (Delivery-fähig)

## Definition of Done
- Umsetzungsteams haben klare technische Richtung
